# 我的小车｜STM32 四路红外循迹小车

> 基于 **STM32F103C8** 的双电机智能循迹小车。使用 **C 语言 + STM32F10x 标准外设库** 开发，通过四路红外传感器识别地面黑线，结合 GPIO、定时器 PWM 和外部中断，实现基于规则判断的循迹与转向控制。

**项目定位：** STM32 单片机入门与智能小车控制实践。仓库保存的是实际编写的 Keil 工程源码，并非已完成全面测试的成品固件。

## 1. 项目简介

小车利用安装在车体前方的四路红外传感器读取地面反射情况，再根据传感器组合控制左右电机的转动方向和 PWM 占空比，从而执行直行、方向修正及部分急转弯处理。

软件主要分为以下几部分：

- **环境感知：** 读取四个数字红外循迹传感器的高低电平。
- **运动执行：** 左右电机分别控制方向和速度，允许不同的输出组合。
- **循迹决策：** 根据传感器组合直接匹配相应的电机指令。
- **中断辅助：** 传感器下降沿触发 EXTI，在中断服务函数中设置急转标志，主循环处理动作。
- **本地显示与指示：** 提供 OLED 显示函数和 LED 指示灯驱动。

当前实现属于**基于条件判断的规则式循迹**，不是 PID、编码器闭环调速、视觉识别或自主路径规划。

## 3. 已编写的功能模块

### 3.1 左右电机独立控制

- 左侧：`Motor_Init()`、`Motor_SetSpeed(int8_t Speed)`。
- 右侧：`Motor_Init_Right()`、`Motor_SetSpeed_Right(int8_t Speed_Right)`。
- 正负速度值用于切换电机方向，绝对值用于设置 PWM 比较值。
- 源码注释将速度参数设计为 **-100～100**，表示反向到正向的 PWM 控制范围；**不是实测转速，也没有速度反馈闭环**。

电机的真实前进方向受布线、电机安装方向以及驱动板连接方式影响，不能仅凭参数的正负号判断车体运动方向。

### 3.2 四路红外黑线检测

`Hardware/Sensor.c` 使用 PA8～PA11 输入四路传感器，并配置为上拉输入。根据源码中的传感器说明：

- **0（低电平）：** 检测到黑线。
- **1（高电平）：** 未检测到黑线。

这一极性来自本项目所采用的传感器逻辑。若更换传感器模块，需要重新核对输出极性与触发阈值。

### 3.3 基于条件判断的循迹

`Hardware/Turn.c` 中的 `Turn()` 检查四路输入组合，并给左右电机发送相应命令。当前规则涵盖：

- 两个内侧传感器检测到黑线时的直行指令。
- 单个内侧或外侧传感器检测到黑线时的方向修正。
- 特定多传感器组合下，设置额外转向标志 `A`、`B`。

当前实现没有建立全组合状态表；没有匹配到的输入组合不会自动生成新的循迹策略。控制参数和动作方向仍需依据实车调试。

### 3.4 外部中断辅助急转

`Sensor_Init()` 将 PA8～PA11 配置为**下降沿触发**的 EXTI：

- PA8、PA9 使用 `EXTI9_5_IRQHandler()`。
- PA10、PA11 使用 `EXTI15_10_IRQHandler()`。
- 中断处理函数通过 `Turn_R_Fast` 或 `Turn_L_Fast` 标志请求急转。
- 主循环读取标志、设置电机输出，再清除标志。

此设计将主要电机动作留在主循环中，避免直接在中断服务函数内完成较长的转弯动作。**注意：实际 ISR 判断条件与注释中的“双传感器同时检测到黑线”并不完全一致**，见后面的已知限制。

### 3.5 OLED 与 LED

- OLED：`Hardware/OLED.c` 使用 PB8（SCL）和 PB9（SDA），通过 GPIO 模拟串行时序，提供数字、字符串等显示函数。
- LED：`Hardware/Led.c` 使用 PA7，低电平点亮、高电平熄灭。
- 主程序已调用 OLED 和 LED 初始化；OLED 目前主要用于调试传感器读数，LED 的动态开关逻辑没有在活动主循环中启用。

## 5. PWM 配置与调速原理

左右通道分别由 TIM2 和 TIM3 输出，源码中的计数参数相同：

- 预分频器：`PSC = 36 - 1`
- 自动重装值：`ARR = 100 - 1`
- PWM 模式：`TIM_OCMode_PWM1`
- PWM 比较值随电机速度指令的绝对值变化

当相关定时器输入时钟为 **72 MHz** 时：

```text
PWM 频率 = 72 MHz / (36 × 100) = 20 kHz
```

该数值是**基于 72 MHz 定时器时钟的理论计算**，并非示波器实测结果。定时器时钟配置或系统时钟不同，实际 PWM 频率也会变化。

## 6. 主程序执行过程

主程序位于 `user/main.c`，活动代码的主要流程为：

```text
系统启动
   │
   ├─ Sensor_Init()           配置四路红外输入及 EXTI
   ├─ Key_Init()              按键初始化（实现文件缺失）
   ├─ OLED_Init()             初始化 OLED
   ├─ Motor_Init()            初始化左电机及其 PWM
   ├─ Motor_Init_Right()      初始化右电机及其 PWM
   └─ LED_Init_zhishideng()   初始化 LED
   │
   ▼
while(1)
   ├─ 尝试显示传感器状态
   ├─ 先设置两路电机输出为 0
   ├─ Turn() 根据当前传感器组合控制电机或设置标志
   ├─ 处理 Turn_R_Fast、Turn_L_Fast 急转标志
   └─ 处理 A、B 转弯标志（部分动作包含 220 ms 延时）
```

其中 `A`、`B` 对应的转向处理使用固定电机指令与 `Delay_ms(220)`。此外，`Turn()` 中也有 `Delay_ms(100)` 的处理分支。这属于**阻塞式定时控制**，未使用编码器或闭环位置测量来判断转弯是否完成。

## 8. 下载、编译和使用

1. 克隆仓库，或者在 GitHub 中选择 **Code → Download ZIP**。
2. 安装 Keil MDK-ARM（µVision）；原项目使用 ARM Compiler 5 和 STM32F1xx 设备支持包。
3. 用 Keil 打开根目录下的 `project.uvprojx`，确认 Target 设备选择为 STM32F103C8。
4. **先补齐缺少的 `Hardware/Key.c`**，或者自行调整工程及主程序中依赖的按键初始化；不要在缺少实现的状态下假定可以编译通过。
5. 检查外设接线、定时器与 GPIO 配置、电机方向以及电源。
6. 执行 Build，并根据实际下载器（例如 ST-Link）配置下载/调试选项。若需要 HEX 文件，还需要检查 Keil 的输出设置。

```bash
git clone https://github.com/huoguoyou486-cmyk/my-car.git
```

**硬件安全提醒：** 单片机 GPIO 不能直接给直流电机供电，应使用匹配的电机驱动电路，确保电源电压、驱动电流和共地关系正确。首次调试建议让车轮离地，先验证单侧电机与 PWM 方向，再进行地面循迹测试。

## 9. 已知问题与当前限制

本仓库优先保证**如实记录现有代码**，下列情况尚未修复或验证：

1. **按键实现文件缺失：** 有 `Key.h` 和主程序中的 `Key_Init()` 调用，但原始压缩包没有 `Hardware/Key.c`。原工程的本地绝对路径引用已改成相对路径，仍必须补齐文件或移除调用才能完成构建。
2. **急转方向逻辑需要检查：** 主程序中 `Turn_R_Fast` 与 `Turn_L_Fast` 分支目前设置了相同的左右电机命令，尚不能据此确认能够区分左右急转。
3. **中断判断条件与注释不完全一致：** 中断实际分别检查 `R_Max == 0`、`L_Max == 0`，并未同时判断注释提到的两路传感器都为低。
4. **OLED 读数可能被覆盖：** 主循环连续将四个传感器读数显示到同一个位置 `(1,7)`，不等于已经实现完整的四路实时状态界面。
5. **按键启停与 LED 状态联动未启用：** 主程序中存在相关历史注释，但当前循环并没有使用按键来切换电机启停，也没有按运行状态持续更新 LED。
6. **转向仍需实机标定：** 部分控制分支采用固定速度和阻塞延时，没有速度反馈、转角反馈或自适应参数。
7. **尚未做本次版本的编译和实机复核：** 不保证在所有 Keil 环境下开箱即用。请结合实际主控、驱动板、供电与接线检查。
